Authorized operational repair after the first two sequential screen blocks and
their initial audit. Their generations, labels, timing and exact raw receipts
are already observed and retained. No main outcome exists. Slower-than-planned
throughput motivated this amendment, not the direction of any report label.

Keep the existing A5 pod, server, weights, worker freeze, deadline, prior costs,
$25 GPU / $45 judge / $5 recovery / $75 total limits and $20 pilot stop-loss.
There is no restart, new pod, prompt/seed/output-cap change or replacement trial.
The scientific inventories, original block order, instruments, qualification
thresholds and two-comparison primary family remain unchanged. Full qualification
still requires all 12 screen blocks. The first two blocks are not rerun or pooled
with the fresh 32-block main. No adaptive concurrency increase is permitted.

For the ten remaining screen blocks and conditional main, send fixed waves
within each existing block: up to two source requests, then up to four finals.
Main's four sources and eight finals therefore require two waves of each role.
Each final waits for its exact donor's completed final content. Reasoning stays
separate; missing donors and all cap/quality flags retain their original rules.
Only the journal-owning thread writes dispatches, exact raw bodies and wave
receipts. Worker threads perform HTTP only, with the unchanged 300-second total
deadline. A failure or external stop blocks new waves and drains current calls;
ambiguous generation calls remain unresolved and are never resent.

Target judging uses a fixed maximum of eight concurrent logical judgments,
with per-call retry ownership and atomic guard/reservation/dispatch. It retains
the separate frozen judge routes, instruments, 600-second HTTP deadline, two
additional identical transport attempts with 2/5-second waits, and validated
refusal-as-missing continuation without retry. No valid label, cap, refusal or
identity failure is retried. External stop persists; admitted attempts drain
and unresolved charge holdbacks remain reserved. Main judging still follows
saved retrieval and direct GET404 deletion of the generation pod. The original
32 target judge responses total 151.719 seconds (mean 4.7412 seconds); the serial
1024-call main tail is about 81 minutes, not five hours. Concurrency does not
reduce call counts or justify a lower reservation or different cost forecast.

Batching can change floating-point scheduling; identical outputs relative to
serial serving are not claimed. The release must identify the sequential prefix
and batched remainder. This is an outcome-aware operational amendment, not an
outcome-naive preregistration or a causal architecture comparison.

Before main, use every completed post-amendment screen wave (10 source waves,
10 final waves), including the slowest. Forecast GPU wall time as
`1.30 * (64 * mean_source_wave_seconds + 64 * mean_final_wave_seconds) + 600`.
Wave timing starts before preflight checks and includes HTTP, raw settlement
and the pre-close audit; the saved UTC start supports wall-clock reconstruction.
Keep the original individual-request forecast visible as a diagnostic, not the
admission criterion after this amendment. The unchanged measured judge forecast,
qualified full screen, remaining owned-pod deadline and all cumulative category
limits must also pass. No favorable-label stopping or extra benchmark calls.
