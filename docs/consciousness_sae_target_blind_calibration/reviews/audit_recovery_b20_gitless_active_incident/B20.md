# B20: Git `/dev/null` failure before scientific execution

The authorized recovery reached its final Landlock-confined process, then failed while final validation invoked `git rev-parse`. Git opens `/dev/null` during startup; the deliberately narrow device policy denied that write-capable open. The failure occurred before `ATTEMPT_STARTED.json`, and no audit, summary, publication marker, or scientific result was produced. The exact owned pod was deleted, while the before/after account inventories remained unchanged.

The final successor fix is Git-free final validation: all Git-derived bindings are resolved and bound before the final confined validator, which performs no Git subprocess call. The Landlock policy is not broadened with a `/dev/null` exception. The successor qualification must exercise that exact Git-free path under the final confinement policy before a fresh one-shot authorization is issued.

This directory is the repo-sized evidence view. It contains self-hashed attempt/output inventories, compact launch-to-authorization-to-Landlock bindings, the exact failure statement and stack symbols, lifecycle receipts, and cryptographic anchors to the omitted private archive. It intentionally excludes the multi-megabyte authorization/import blobs and full retrieved attempt tree. Therefore it verifies the portable bundle and its anchors; independent re-hashing of every omitted source file requires the retained private archive.
