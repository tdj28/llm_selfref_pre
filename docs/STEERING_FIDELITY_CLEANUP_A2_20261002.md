run. The complete worker inventory was observed at 9,300 forced-choice
forwards and 40 liveness files, followed by exit code 0. This is an inventory
observation, not a scientific gate verdict.

was quiescent. Repeated `TimeoutExpired` failures occurred before a new
snapshot directory was created. The inherited remote-manifest command had a
60-second timeout. No final receipt or deletion had been issued. Previous
retrievals and retry events remain in the append-only lifecycle record.

manifest command's timeout (60 to 300 seconds) and retrieval rsync timeout
(300 to 900 seconds). It uses the existing scientific runtime, A1 binding,
ownership checks, final hash verification, single-delete permission and GET404

and prior worker-quiescence evidence. It cannot create a pod, dispatch a
worker, or change a scientific setting. Its source hash and effective timeouts
are recorded in the original lifecycle before attempting cleanup.

The old local monitor was stopped before the replacement ran; its remote
worker was already stopped. Original source/plan hashes, budget accounting,
retry records and raw data remain unchanged. The spending caps are unchanged.
Longer transport timeouts do not guarantee a provider billing ceiling.

values and redacted error messages. These are transport tests, not a completed
