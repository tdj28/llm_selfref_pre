# Kolibri Startup A4

This authorized operational repair changes installation storage and transient
provider reads, not the scientific design or the CUDA qualification.

A3 ended before qualification. Its controller recorded a provider GET timeout,
retrieved the worker log and exit143, and verified owned-pod deletion by GET404.
The log ended during package installation. Observed process I/O supports a
network-filesystem bottleneck, but does not establish its underlying cause.
All four failed startup attempts remain unchanged; no research/target outcomes
were collected. Earlier parser and technical fixture outcomes were known.

The venv and pip cache move to container-local `/tmp`. Before installation, the
worker records the filesystem type, available bytes, and separation from the
workspace mount. It requires 35 GiB free on local disk. The same locked packages,
plugin, model files, original settings, and A3 exact FP8 reconstruction test run.
Weights remain on the remote workspace volume, not on the operator's computer.

Only transient provider GET failures receive at most two additional attempts,
after 2 and 5 seconds. Each attempt checks the remaining deadline and cost with
the existing 600-second cleanup reserve. POST and DELETE are never resent by
this adapter. Cleanup retains the existing bounded direct-GET confirmation loop
without stacking inner retries. Exhaustion preserves the error and invokes the
existing retrieval/deletion path; there is no automatic replacement pod.

The cumulative startup cap becomes $2 and the main cap $23, within the unchanged
$25 GPU and $75 study ceilings. Startup admission carries
$1.02856524106372729000000001, rounded upward from every prior attempt. Judges
retain $45 and storage/recovery $5. The original combined $20 pilot stop-loss,
fixed screen/main inventories, measured whole-main forecast and 30% margin remain.

Both controller and production use the canonical `bootstrap-a4` output root.
Main requires a passed, hash-verified A3-computation receipt from the A4 cheap
attempt plus direct GET404. The bridge retains judge policy freeze
`444a1a181f1056e24d18ebe89f93a941810dd2e4` byte-for-byte, including its original
A2 worker reference; the separate bridge explicitly binds the new worker freeze.
Final judging waits for main generation, retrieval and deletion. No scientific
gate is repaired retrospectively.

candidate; it does not rent or authorize a pod.

judge-screen-initial, generate-screen, judge-screen, main-admission,

reconciliation; generation also needs the owned loopback SSH tunnel. Credentials
remain local and are never printed or sent to the GPU worker. Source-bound unit
tests are synthetic and do not establish CUDA qualification.
