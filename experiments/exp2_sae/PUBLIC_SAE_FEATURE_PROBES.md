# Public SAE Feature Semantics Probes

This note documents the no-key path for testing the public AE notebook candidate feature IDs against the public Goodfire HuggingFace SAE.

## Purpose

The AE public notebook gives candidate Llama 3.3 70B layer-50 feature IDs and saved labels, but it does not provide full feature cards, top activating examples, or enough metadata to prove what the features encode. The probe harness asks a narrower question:

> Do the candidate features selectively activate on deception/cover-story text, or do they also activate on roleplay, fiction, persona maintenance, hedging, refusals, AI disclaimers, self-reference, consciousness claims, or false self-attribution?

This does not reproduce proprietary Steering API steering. It is a public-weight activation semantics check.

## Provenance Boundary

Our code and prompt battery:

- `experiments/exp2_sae/probe_public_sae_features.py`
- The text probe categories and examples inside that script.
- The CSV/JSONL summaries generated by the script.

External factual inputs:

- Candidate feature IDs and labels are taken from AE Studio's public notebook saved outputs, as documented in `experiments/exp2_sae/AE_STEERING_NOTEBOOK_FINDINGS.md`.
- Public SAE weights are loaded from `Goodfire/Llama-3.3-70B-Instruct-SAE-l50`.
- The base model is `meta-llama/Llama-3.3-70B-Instruct`.

The script does not vendor the upstream notebook or copy its code. Treat its candidate IDs as unconfirmed paper-relevant IDs unless the authors or Goodfire / Steering API confirm otherwise.

## Dry Run

Use dry-run mode locally to validate the battery and manifest without downloading models:

```bash
python experiments/exp2_sae/probe_public_sae_features.py \
  --dry-run \
  --max-items-per-category 2 \
  --outdir data/public_sae_feature_probes_dryrun
```

Expected outputs:

- `manifest.json`
- `probe_items.csv`

These outputs live under `data/`, which is ignored by git.

## Live 70B Probe

Run this on a large GPU pod after HuggingFace access is configured:

```bash
python experiments/exp2_sae/probe_public_sae_features.py \
  --model-alias 70b \
  --device auto \
  --dtype bfloat16 \
  --text-format raw \
  --outdir data/public_sae_feature_probes/70b_public_ids
```

If memory is tight, try quantization:

```bash
python experiments/exp2_sae/probe_public_sae_features.py \
  --model-alias 70b \
  --device auto \
  --dtype bfloat16 \
  --load-in-4bit \
  --text-format raw \
  --outdir data/public_sae_feature_probes/70b_public_ids_4bit
```

The harness captures activations at the public model's `model.layers.50` hook, applies only the selected public SAE encoder rows, and writes per-item and per-category summaries.

## Outputs

Live runs write:

- `manifest.json`: model, SAE, feature IDs, args, claim boundary.
- `probe_items.csv`: clean-room probe battery with text hashes.
- `activations.jsonl`: per item x feature activation metrics.
- `category_feature_summary.csv`: mean activation by feature and category.
- `feature_category_rankings.csv`: category ranking per feature.
- `feature_specificity_summary.csv`: deception-vs-neutral and deception-vs-confound contrasts.

The key table for interpretation is `feature_specificity_summary.csv`.

| `23893` | deception/cover-story | 0.42 | persona maintenance | 0.38 |

Interpretation:

- The candidate IDs are not arbitrary: five of six top out on deception/cover-story text, and the explicitly roleplay-labeled feature top-outs on roleplay/persona text.
- Fiction/pretending is the strongest non-deception confound for four features, which matters because "roleplay/deception" labels can overlap with narrative style rather than hidden honesty.
- This supports public label plausibility, but it does not test steering, aggregate effects, TruthfulQA, random-feature baselines, or false-self-attribution under steering.
- It should be cited as activation semantics evidence, not as an exact proprietary API replication.

## Interpretation

Helpful outcomes for the paper:

- If deception/cover-story text is clearly above neutral and above all confound categories, then the public labels look more plausible and we should report that.
- If roleplay, fiction, persona-maintenance, disclaimer, self-reference, direct-consciousness, or false-self-attribution categories match or exceed deception activations, then the paper's "deception gating" interpretation is underdetermined.
- If candidate IDs barely activate or activate mostly on unrelated text, then the public IDs are not enough to support the paper's mechanistic interpretation.

Safe claims:

- "Using public SAE weights and public candidate IDs, activation semantics do/do not support a selective deception interpretation."
- "This is not an exact proprietary API replication."
- "The result informs interpretation of the public artifact, not the private paper run unless IDs and API version are confirmed."

Unsafe claims without more access:

- "The exact Goodfire / Steering API result is false."
- "The authors used the same exact notebook run."
- "The feature IDs are stable across private API and public HuggingFace weights."

## 8B Debugging

The AE notebook feature IDs are 70B layer-50 IDs. For 8B debugging, supply explicit 8B feature IDs:

```bash
python experiments/exp2_sae/probe_public_sae_features.py \
  --model-alias 8b \
  --feature-ids 123,456,789 \
  --device auto \
  --outdir data/public_sae_feature_probes/8b_debug
```

Do not interpret 8B user-supplied IDs as reproducing the AE notebook unless they were independently mapped to that SAE.
